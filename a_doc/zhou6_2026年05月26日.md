# zhou6_2026年05月26日

## 今日认证链路与安全改动汇总

### 1. 前端统一访问网关

当前微服务访问约定为：

```text
前端 -> gateway-service -> auth-service / user-service / 其他业务服务
```

前端不要直接访问具体微服务，统一请求网关地址。

示例：

```http
POST /auth/login
POST /auth/refresh
POST /auth/logout
POST /userInfo/info
```

### 2. Token 使用方式

登录成功后，后端返回 `accessToken` 和 `refreshToken`。

前端访问需要登录态的业务接口时，在请求头携带：

```http
Authorization: Bearer <accessToken>
```

前端只负责保存 token 和请求时携带 token，不负责验证 token 真伪。

后端负责校验：

- token 是否存在
- token 签名是否正确
- token 是否过期
- token 中的 `sessionId` 是否仍是 Redis 当前会话

校验失败时，后端返回 `401`，前端按登录失效处理。

### 3. Token 过期处理

`accessToken` 的过期时间由后端签发时确定，不会因为用户还停留在页面上自动延长。

推荐前端处理流程：

```text
业务接口返回 401
  -> 使用 refreshToken 调用 /auth/refresh
  -> 刷新成功后更新 accessToken 和 refreshToken
  -> 重试原业务请求
  -> 刷新失败则清除本地 token 并跳转登录页
```

### 4. 新增退出登录

新增退出接口：

```http
POST /auth/logout
Content-Type: application/json
```

请求体：

```json
{
  "refreshToken": "登录或刷新接口返回的 refreshToken"
}
```

退出接口不需要携带 `Authorization`，通过网关白名单放行。

后端退出时会根据 `refreshToken` 删除 Redis 中的当前登录态：

- `zhou6:auth:refresh:{refreshToken}`
- `zhou6:auth:session:{userId}`
- `zhou6:auth:current-refresh:{userId}`
- `zhou6:auth:login-ip:{userId}`

前端退出成功后，还需要清除本地保存的 token：

```js
localStorage.removeItem('accessToken')
localStorage.removeItem('refreshToken')
```

| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/controller/AuthController.java` | 新增 `/auth/logout` |
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/service/AuthService.java` | 新增 `logout` 服务接口 |
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/service/impl/AuthServiceImpl.java` | 删除 Redis 登录会话和刷新令牌 |

### 5. 网关和微服务接口调用日志

已增加网关和微服务接口访问日志。

日志字段：

- `service`
- `method`
- `path`
- `status`
- `durationMs`
- `clientIp`

示例：

```text
service=gateway request method=POST path=/auth/logout status=200 durationMs=12 clientIp=127.0.0.1
service=auth-service request method=POST path=/auth/logout status=200 durationMs=8 clientIp=127.0.0.1
```

日志不打印以下敏感内容：

- 请求体
- query 参数
- password
- accessToken
- refreshToken
- Authorization 请求头

涉及代码：

| 模块 | 文件 | 说明 |
|---|---|---|
| gateway-service | `gateway-service/src/main/java/com/zhou6/cloud/gateway/filter/GatewayAccessLogFilter.java` | 网关全局接口日志 |
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/filter/AccessLogFilter.java` | 认证服务接口日志 |
| user-service | `user-service/src/main/java/com/zhou6/cloud/user/filter/AccessLogFilter.java` | 用户服务接口日志 |

### 6. 敏感参数不再放 URL

之前用户校验接口使用 URL query 传递账号密码：

```http
POST /userInfo/verify?username=xxx&password=xxx
```

该方式存在风险，因为 URL 可能进入浏览器历史、网关日志、代理日志、链路追踪和异常日志。

已改为 JSON body：

```http
POST /userInfo/verify
Content-Type: application/json
```

```json
{
  "username": "xxx",
  "password": "xxx"
}
```

涉及代码：

| 模块 | 文件 | 说明 |
|---|---|---|
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/dto/VerifyRequest.java` | 新增用户校验请求 DTO |
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/client/UserClient.java` | Feign 改为 `@RequestBody` |
| auth-service | `auth-service/src/main/java/com/zhou6/cloud/auth/service/impl/AuthServiceImpl.java` | 调用用户服务时传 JSON body |
| user-service | `user-service/src/main/java/com/zhou6/cloud/user/dto/VerifyRequest.java` | 新增用户校验请求 DTO |
| user-service | `user-service/src/main/java/com/zhou6/cloud/user/controller/UserController.java` | `/userInfo/verify` 改为接收 `@RequestBody` |
| user-service | `user-service/src/test/java/com/zhou6/cloud/user/UserInfoApiTest.java` | 测试用例同步改为 JSON body |

### 7. 前端接口约定汇总

登录：

```http
POST /auth/login
Content-Type: application/json
```

刷新：

```http
POST /auth/refresh
Content-Type: application/json
```

退出：

```http
POST /auth/logout
Content-Type: application/json
```

```json
{
  "refreshToken": "xxx"
}
```

业务接口：

```http
Authorization: Bearer <accessToken>
```

统一约定：

- 所有接口统一请求 `gateway-service`
- 登录、刷新、退出不需要 `Authorization`
- 其他业务接口需要 `Authorization: Bearer <accessToken>`
- 前端不解析 token，不判断 token 真伪
- 后端返回 `401` 时，前端尝试刷新 token 或跳转登录页
